# SmartStore AI

SmartStore AI is a React + TypeScript + Vite storefront workspace backed by Django REST Framework. The backend uses MySQL for its configured database, JWT authentication, store-scoped APIs, optional Gemini inventory chat, and bounded CSV/XLSX product import.

## Local setup

Configure `backend/.env` from `backend/.env.example`. Keep real credentials only in the ignored `.env` file. The settings load that file directly; values are never needed in source control.

Required settings include `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, and a Gemini API key/model for AI chat. The default frontend API base is `http://127.0.0.1:8000/api`; set `VITE_API_BASE_URL` if your backend is elsewhere. CORS defaults allow Vite on ports 5173 and 5174.

Checkout uses `ORDER_CURRENCY=INR` and `ORDER_DELIVERY_CHARGE=0.00` by default. COD works without a payment provider. Razorpay is disabled until `RAZORPAY_MODE=test`, `RAZORPAY_KEY_ID` (`rzp_test_…`) and `RAZORPAY_KEY_SECRET` are set in the ignored `backend/.env` file. Never put the secret in a `VITE_` variable. Set real credentials and `RAZORPAY_MODE=live` only for an intentional production launch.

Store slugs are generated by Django from the store name and made unique (for example, `Sweet Store` becomes `sweet-store`, then `sweet-store-2`). Published stores are served from the shared frontend at `/store/{slug}`. Set `VITE_PUBLIC_APP_URL` to the public frontend origin for deployed links; if unset, the app uses the browser's current origin. Configure production static hosting to serve the Vite `index.html` fallback for `/store/*` so direct links and refreshes reach React. The QR download button requests a PNG from QRServer using the public storefront URL.

```powershell
# Backend, from repository root
.venv\Scripts\Activate.ps1
python backend\manage.py migrate
python backend\manage.py runserver

# Frontend, in another terminal
cd frontend\smartstore-ai-react
npm install
npm run dev
```

The configured MySQL database is the application database. `backend/db.sqlite3` is retained as the legacy source and available through the `sqlite_legacy` Django alias; it is not used as an automatic fallback if MySQL is unavailable. Existing SQLite records were copied into MySQL. A timestamped SQLite backup from before the schema migration remains beside the source file.

In development, uploaded logo and banner files are served at `/media/` from `backend/media/` (ignored by Git). Production must use durable media storage and configure the web server or storage provider to serve those files; Django's development media route is disabled when `DEBUG=false`.

## API summary

All paths are prefixed with `/api/`. Protected routes require `Authorization: Bearer <access>`.

- `POST /auth/register/` accepts username, email, and password (at least 8 characters).
- `POST /auth/login/` accepts email and password and returns access and refresh JWTs.
- `GET /auth/me/` returns the authenticated user.
- `GET, POST /stores/`; stores are tenant-scoped by membership. `POST /stores/{id}/assets/` accepts multipart `logo_image` and/or `banner_image` uploads (with size limits); development serves stored media from `/media/`.
- `GET /stores/slug-availability/?slug=...` checks a normalized slug.
- `GET, POST /stores/{slug}/categories/`; `POST /stores/{slug}/categories/bulk/` creates categories.
- `GET, POST /stores/{slug}/products/`; `GET, PATCH, DELETE /stores/{slug}/products/{id}/`.
- `POST /stores/{slug}/products/import/` accepts CSV or XLSX, limited to 10 MB. Send `commit=false` to preview (default), then `commit=true` to persist validated rows. Required headers: `name`, `price`, `stock`, `category`; optional headers: `sku`, `description`, `image_url`. Category must match an existing category in the same store. Spreadsheet formulas/macros are not executed; XLSM is rejected. `GET /stores/{slug}/products/import/template/` downloads an authenticated store-aware XLSX template.
- `GET, PATCH /stores/{slug}/theme/`; `POST /stores/{slug}/publish/` records publication intent and returns a relative path. It does not deploy hosting, DNS, or a custom domain.
- `GET /stores/{slug}/analytics/` returns the supported recent order and low-stock summary. Revenue/order history remains unavailable until order records exist.
- `POST /ai/chat/` accepts `{ "store_slug": "...", "question": "..." }`. It requires authentication and store membership. The backend sends bounded inventory facts for that store to Gemini; it provides no database tools. Rate limit: 10 requests per minute per user. The endpoint returns 503 when Gemini configuration is missing and a generic 502 on provider failure.
- `GET /public/stores/{slug}/` and `GET /public/stores/{slug}/products/{id}/` expose published store data.
- `GET /public/stores/{slug}/checkout/config/` exposes currency, delivery charge, COD availability and whether server-side Razorpay credentials are configured.
- `GET /public/stores/{slug}/` serves a published store's public theme, contact details, non-demo categories, and active products for that store only. Customer product responses omit SKU and internal low-stock thresholds.
- `POST /public/stores/{slug}/checkout/` requires JWT and an `Idempotency-Key` UUID header. Submit customer details, delivery address and product ID/quantity pairs. The server verifies store, product, stock, current prices and calculates totals before reserving stock and saving an order; browser prices are ignored.
- `POST /orders/{order_number}/payment/create/`, `/payment/verify/`, and `/payment/fail/` are customer-owned Razorpay operations. The server creates provider orders and verifies the HMAC plus Razorpay payment state/amount. Card details are handled by Razorpay Checkout and are not stored here. No online success is reported until provider verification succeeds.
- `GET /orders/my/`, `GET /orders/my/{order_number}/`, and `POST /orders/my/{order_number}/cancel/` provide authenticated customer order history, detail and eligible cancellation.
- `GET /stores/{slug}/orders/`, `PATCH /stores/{slug}/orders/{order_number}/status/`, and `POST /stores/{slug}/orders/{order_number}/payment/collect/` provide membership-scoped order management and COD collection confirmation. Payment and fulfilment statuses are separate. Paid-order refunds are not automated.

## Checks

```powershell
python backend\manage.py check
python backend\manage.py makemigrations --check --dry-run
python backend\manage.py check_gemini
cd frontend\smartstore-ai-react
npm run build
```

Backend tests use the configured database to create a test database. If a test database already exists, do not approve its deletion unless it is disposable. An in-memory SQLite test settings module can be used for isolated local tests.

## Current product limits

The owner sidebar keeps one Create Store Website entry point; the no-store state directs authorized users to store setup. Order management and customer order history share an authenticated Orders page, and checkout is available from the storefront cart for a published store. All Themes includes themed page previews for home, login, signup, catalogue, product, cart, checkout, and tracking. These previews are not a separate deployed customer application. Demo products are marked as demo and excluded from inventory analytics/assistant facts. Image fields accept URLs; binary image storage needs a storage service. Editable homepage blocks, DNS/custom domains, and hosted deployment are not implemented. Storefront preview does not itself publish a public deployment. Online payments require valid Razorpay credentials and a configured callback flow; no live provider transaction is implied by the local tests.
